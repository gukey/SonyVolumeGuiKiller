# 自动 5555 辅助服务 0.3.5-sony.1

基于原作者 [mouldybread/adb-auto-enable v0.3.5](https://github.com/mouldybread/adb-auto-enable/tree/v0.3.5)，上游提交 `23a8e988f29b349ac0dc58415c18e6229f20750d`，保留 MIT 许可证。此处是索尼工具配套修改版，不是原作者官方 APK。

包名 `com.tpn.adbautoenable.fix`，versionCode 15，Android 8.0 及以上。音量屏蔽 APK 仍为 1.0.4；两个应用用途不同，需配合使用。

## 持续守护

- 启动、系统重建服务后都进入持续循环。正常每 15 秒验证一次 ADB 认证及 shell 回显；失败后按 5/10/20/40/60 秒间隔无限重试。
- 屏幕点亮和网络变化合并为一次补查。网页的测试/切换请求交给同一个守护线程，避免并发恢复相互干扰。
- ADB 握手等待 5 秒，单次操作 12 秒触发中断和连接关闭。底层网络仍卡住时，独立心跳在清醒运行 120 秒无进展后终止本应用进程，交由 START_STICKY 和系统任务尝试重建，释放旧 socket 与线程。此措施不重启电视。
- 保留上游 connectedDevice 前台服务及启动保护；增加每 15 分钟的系统任务作为进程回收后的补救。系统任务可能延迟，不代表能在固定时间内恢复。
- 关闭网页管理界面不会停止 ADB 守护。状态接口增加 `guardHealthy`、`lastGuardCheck`，区分端口开放与近期真实命令成功。
- 配对/连接必须返回成功；端口切换后重新验证命令执行。异常不会终止后续循环；端口扫描结束取消未完成任务。
- 读取授权文件失败时保留原身份，不自动覆盖生成新密钥；密钥加载串行化。首次解锁前等待现有授权文件可访问，解锁后恢复。

普通 Android 应用无法保证被用户强行停止、撤销权限或系统禁止自启动后仍持续运行。上述机制用于自动发现并恢复常见故障，不能宣称“永不掉线”。不要禁用辅助 APK，否则音量守护可能失去 ADB 执行通道。

## 构建

JDK 17、Android SDK 35，使用随附 Gradle 8.13 / AGP 8.9.2：

```powershell
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

输出 `app/build/outputs/apk/debug/app-debug.apk`。为了兼容现有 EXE 的 `run-as` 授权流程，使用 debug 构建。libadb 使用 3.1.1，Conscrypt 2.5.2，Bouncy Castle 1.81，统一依赖避免重复类；这些构建配置与上游发布流水线有区别。

## 更新与验证

旧辅助包是 0.2.7-codex-fix。版本号升高不代表一定能覆盖安装：本机编译签名与旧包不同，安装前必须备份 APK 和授权文件，迁移后再验证；不要直接卸载而丢失已配对身份。新 APK 不包含用户密钥。

自动测试覆盖无响应 socket 的超时关闭、操作完成后取消超时、重试上限、卡死阈值和上游 TCL 策略。编译和静态检查通过不等同于电视长期稳定性验证。

电视验收需记录：正常连续运行、待机唤醒、ADB 端口中断后恢复、辅助进程被回收后恢复、网页关闭后仍守护，以及音量屏蔽是否随之恢复。真实设备测试结果另行记录，未完成项目不得标为通过。

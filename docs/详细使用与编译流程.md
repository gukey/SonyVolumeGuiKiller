# 索尼电视音量弹窗管理工具：详细使用与编译流程

适用于本文件夹内的版本：音量屏蔽 APK **1.0.4**、自动 5555 APK **0.3.5-sony.1**、PC 客户端 **1.0.5（含默认 IP 修改）**。源码快照为 `d9565db`。

普通使用只需阅读第 1～7 节；需要修改程序或重新编译，再阅读第 8～10 节。

## 1. 这个项目解决什么问题

在已验证的索尼 Android TV 固件上，隐藏按音量键时出现的系统音量弹窗，同时保留遥控器调节音量的功能。它不负责静音，也不锁定音量大小。

整个项目包含三个程序：

| 程序 | 安装或运行位置 | 作用 | 当前版本 |
| --- | --- | --- | --- |
| 音量弹窗屏蔽 APK | 电视 | 通过无障碍事件和周期检查，清除系统音量 GUI 控制器 | 1.0.4 |
| 自动恢复 5555 APK | 电视 | 保持本地 ADB 执行通道可用；失败后发现无线调试端口并尝试恢复 5555 | 0.3.5-sony.1 |
| PC 管理客户端 | Windows 电脑 | 连接电视、安装程序、写入授权文件、启用服务、诊断与查看日志 | 1.0.5 |

日常运行关系：**自动 5555 辅助服务提供 ADB 通道 → 音量守护通过该通道执行操作 → 隐藏音量弹窗**。配置成功后，电脑工具可以关闭，两个电视端程序继续工作。

## 2. 文件夹里有什么，应该打开哪个

```text

│  ├─ SonyVolumeGuiKiller-1.0.4-debug.apk
│  └─ 02_AdbAutoEnable5555_自动恢复5555.apk
├─ 02_电脑EXE/
│  ├─ SonyVolumeGuiKillerPcManager.exe    ← 普通用户运行这个
│  ├─ apk/                             ← 必须和 EXE 一起保留
│  ├─ images/
│  └─ 使用说明、辅助服务说明、实测记录

   ├─ adb-auto-enable/                  ← 自动 5555 APK 独立工程
   ├─ pc/                              ← Windows 客户端源码
   └─ docs/                            ← 图文说明与测试记录
```

- `01_电视APK` 中的两个文件都需要使用，它们功能不同，不是新旧版本关系。
- EXE 内嵌自动 5555 APK；旁边 `apk/SonyVolumeGuiKiller-release.apk` 是供工具安装的音量守护文件。这是分发文件名，实际配套版本仍为 1.0.4。
- APK 文件名中的 `debug` 是构建类型。本项目的电脑授权流程需要使用 `run-as` 写入应用私有目录，因此使用可调试构建。
- 源码文件夹用于开发和重新编译，普通用户不用运行里面的文件。
- 请完整保留电脑客户端目录，不要只把 EXE 单独复制到其他位置。

## 3. 第一次使用前的准备

1. 使用 64 位 Windows 电脑，完整解压本汇总文件夹到可写目录，例如桌面。
2. 电脑与电视接入同一局域网。避免使用不能互相访问的访客网络或启用客户端隔离的 Wi-Fi。
3. 在电视设置中找到“关于”，连续点击系统版本/Build 项，直到提示已开启开发者模式。具体菜单名称以电视固件为准。
4. 打开“开发者选项”，启用调试相关开关和“无线调试”。电视若弹出网络调试授权提示，请确认当前网络。
5. 查看电视当前 IP。客户端每次启动默认填入 `192.168.1.111`；如果电视地址不同，直接修改左侧输入框。这里仅填 IP，不带 `http://` 和端口。
6. 运行 `02_电脑EXE/SonyVolumeGuiKillerPcManager.exe`。预编译客户端包含 .NET 运行环境和 ADB，不要求先安装开发工具。

本项目已验证的电视为 **Sony BRAVIA 4K AE2 / Android 14**。其他型号、系统版本或更新后的固件，需要重新确认兼容性。

## 4. 三个输入框怎么填写

![客户端界面示例](images/tool-main.png)

截图中的 IP、端口和配对码是示例，不能直接用于你的电视。实际工具默认 IP 已设为 `192.168.1.111`，但端口和配对码必须看电视当前显示的值。

| 输入框 | 在哪里看 | 填什么 |
| --- | --- | --- |
| ① 配对端口 | 无线调试 → 使用配对码配对设备 → 配对弹窗 | 弹窗中 IP 地址冒号后面的数字 |
| ② 六位配对码 | 同一个配对弹窗 | 六位数字，开头是 0 也要保留 |
| ③ 调试端口 | 无线调试主页面 | 主页面中 IP 地址冒号后面的数字 |

![三个字段填写图解](images/connection-guide.png)

### 4.1 首次配对

1. 先在无线调试**主页面**记下调试端口，填入③。
2. 再打开“使用配对码配对设备”，把弹窗中的配对端口填入①，六位配对码填入②。
3. 保持电视配对弹窗打开，点击电脑工具左侧“连接电视”。
4. 如果电视弹出“允许此电脑调试”的提示，确认允许；仅对自己的可信电脑选择持续允许。
5. 等待工具日志报告连接成功，然后再进行安装或诊断。

注意：①和③通常不同，六位配对码不是端口。关闭或重新打开配对弹窗后，①②可能改变；电视重启或无线调试重新开启后，③也可能改变。

### 4.2 以前配对过

将①②**一起留空**，③填写当前调试端口，点击连接。不要保留过期的配对码。

### 4.3 已经配置好固定 5555

将①②留空，③填 `5555`，点击连接。5555 并不是电视出厂就一定开放，必须先完成相应配置。

## 5. 安装和更新流程

### 5.1 先判断是否需要安装

如果电视上已安装本汇总包对应版本，而且诊断正常，直接使用即可，不需要反复“一键安装”。重新部署会操作电视上的应用和授权配置。

如果是首次安装，或确实需要更新，先连接电视，再按下面步骤操作。

### 5.2 更新前先备份

1. 使用“备份电视 APK”保存原来的安装包。
2. 若更换签名或需要卸载重装，还必须单独备份应用私有授权文件和配置。
3. **安装包备份不等于授权数据备份。** 不要看到 APK 已备份，就直接卸载旧程序。

本次旧辅助包 0.2.7-codex-fix 与新编译包签名不同，不能直接覆盖。现用电视已完成一次备份迁移；在另一台设备上操作，仍要检查它自己的旧包与授权状态。

当前客户端一键部署还会尝试卸载原始包名 `com.tpn.adbautoenable` 的旧辅助应用。如果电视装的是原作者版本，请先备份该应用，确认迁移方式后再执行。

### 5.3 使用“一键安装”

连接成功、备份完成后，点击“一键安装”。程序依次尝试：

1. 安装自动 5555 辅助 APK。
2. 授予所需设置权限，写入本机对应的 ADB 授权身份。
3. 启动辅助程序，触发恢复并等待 5555 可连接。
4. 安装音量守护 APK，写入其授权文件并启用无障碍服务。
5. 重新检查服务和音量拦截状态。

请等日志显示完成再操作其他功能。如果某一步报错，先处理该错误，不要连续点击安装。工具会重启电脑侧 ADB 服务，其他正在使用 ADB 的程序可能暂时断开。

“签名不一致”“INSTALL_FAILED_UPDATE_INCOMPATIBLE”表示不能覆盖安装，不代表应该立即卸载。先保留日志与备份，完成授权迁移后再继续。

### 5.4 安装 APK 后为什么可能还不能用

仅把两个 APK 装进电视，不等于配置完成。还需要有效 ADB 授权、辅助应用的设置权限，以及音量守护的无障碍服务。普通用户优先使用客户端完成这些步骤；手动安装后应逐项核查。

## 6. 如何确认已经正常工作

按以下顺序检查：

1. **连接层**：客户端能连接电视，固定端口 5555 可用。
2. **辅助服务层**：浏览器访问 `http://192.168.1.111:9093`，查看状态和日志。电视 IP 改变时替换地址。
3. **命令执行层**：辅助日志持续出现 `guard health=true`，表示实际 ADB 命令验证成功，而不只是端口开放。
4. **音量守护层**：电视无障碍设置中启用本项目服务；诊断中的 `mVolumeController` 为 `null`。
5. **实际效果**：按遥控器音量键，确认声音大小能变化，系统音量弹窗被抑制。

网页接口 `http://192.168.1.111:9093/api/status` 的关键字段：

| 字段 | 含义 |
| --- | --- |
| `adb5555Available` | 配置的目标端口当前是否可连接 |
| `guardHealthy` | 最近一次有效时间范围内的命令检查结果 |
| `lastGuardCheck` | 最近检查时间，Unix 毫秒时间戳 |
| `isPaired` | 网页配对流程的标记；经 PC 导入有效授权后，它可能仍显示 false |

`guardHealthy` 不是连续实时采样，故障发生后可能短暂保留上次结果，应结合端口状态、时间和日志判断。PC 的无障碍状态显示可能误判，不能只看“健康分数”或一个 disabled 标签就断定服务已停。

## 7. 日常使用与故障恢复

### 7.1 正常使用

配置成功后关闭 PC 工具即可。保留电视端两个 APK、调试授权和无障碍服务。关闭辅助应用的“网页管理界面”开关只关闭网页，不会关闭持续守护；以后需要网页时，在电视辅助应用里重新打开开关。

辅助服务正常约每 15 秒检查一次。失败后按 5/10/20/40/60 秒间隔持续重试，发现和恢复端口本身还需要时间。操作有超时保护；守护长时间卡住时尝试重建本应用进程，不需要以整台电视重启作为常规恢复方式。

### 7.2 按现象排查

| 现象 | 建议处理顺序 |
| --- | --- |
| 连接失败、offline | 确认电视开机、IP 正确；检查当前调试端口。必要时重新打开配对弹窗，重新填写三项 |
| unauthorized | 在电视确认该电脑的调试授权；核对是否换了电脑或 ADB 身份 |
| 配对失败 | 保持配对弹窗打开，使用新配对码与配对端口，不要把③当成① |
| 5555 不可用 | 先用无线调试主页面的当前端口连接；检查辅助服务、权限与授权，不要把 5555 当作始终已开放 |
| 网页访问超时，ADB 正常 | 确认网页开关开启；让本地电视 IP 绕过电脑代理。本次曾验证代理路径可造成超时，直连正常 |
| 5555 正常，音量弹窗仍出现 | 检查音量守护无障碍是否启用、其授权是否有效，以及 `mVolumeController`；必要时关闭再开启该无障碍服务 |
| 更新时签名冲突 | 停止覆盖尝试；保留旧 APK，先备份私有授权数据再迁移 |
| 强行停止应用后不恢复 | 从电视应用列表重新打开该应用，重新检查服务；系统强行停止不能按普通进程回收处理 |

记录故障时，保留发生时间、电视系统版本、两个 APK 版本、客户端错误和相关服务日志。不要分享私有 ADB 密钥或仍有效的配对码。

### 7.3 本次已经验证和未验证的范围

- 辅助进程被终止后，8 秒内观察到系统重建进程并恢复命令验证。
- 将 ADB 临时切到 5566 后，服务自动发现无线调试端口并恢复 5555；从检测故障到恢复约 19 秒。
- 15 秒短时待机后唤醒，守护恢复正常。
- 关闭网页管理后，后台守护继续运行；重新打开网页成功。
- 自动测试 8 项通过，Android lint 0 错误、31 条警告；客户端编译与窗口检查通过。

这是单轮短时验证，不是 24/48 小时耐久测试，也不代表全部索尼固件都兼容。权限被撤销、用户强行停止或系统禁止自启动时，普通应用无法保证持续运行。完整记录见 `03_项目源码/docs/辅助服务实测.md`。

## 9. 重新编译：按顺序操作

以下命令在 PowerShell 中执行。示例从**本汇总文件夹根目录**打开终端开始。预编译版本的普通使用不需要这些开发环境。

### 9.1 准备环境

- JDK 17，并正确设置 `JAVA_HOME`。
- Android SDK：安装 Android 35 平台与相应 Build Tools，设置 `ANDROID_HOME` 指向 SDK 根目录。
- .NET 8 SDK，用于编译 Windows 客户端。
- 第一次 Gradle 构建需要联网下载依赖；网络失败与源码编译失败应分别处理。

SDK 路径可以按本机实际安装位置配置。例如：

```powershell
$env:JAVA_HOME = 'C:\实际安装目录\jdk-17'
$env:ANDROID_HOME = 'C:\实际安装目录\Android\Sdk'
```

不要原样复制上述占位路径。也可以分别在两个 Android 工程中创建自己的 `local.properties` 指定 SDK；不要把个人机器配置或签名密钥作为公共源码发布。

### 9.2 编译音量屏蔽 APK

```powershell
Push-Location '.\03_项目源码'
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug
Pop-Location
```

必须看到 `BUILD SUCCESSFUL`。产物位置：

```text
03_项目源码/app/build/outputs/apk/debug/app-debug.apk
```

### 9.3 编译自动 5555 APK

```powershell
Push-Location '.\03_项目源码\adb-auto-enable'
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
Pop-Location
```

产物位置：

```text
03_项目源码/adb-auto-enable/app/build/outputs/apk/debug/app-debug.apk
```

两个产物都叫 `app-debug.apk`，必须按完整目录分辨，避免拿错！

### 9.4 编译 PC 客户端，并内嵌刚构建的辅助 APK

先运行一次本包的预编译 EXE，它会在旁边释放 `tools` 目录。编译时需要其中的 `adb.exe`、`AdbWinApi.dll`、`AdbWinUsbApi.dll`。也可以通过 `AdbToolsDir` 指定自己准备的官方 platform-tools。

Android 两项构建成功后，从汇总文件夹根目录执行：

```powershell
$bundleRoot = (Get-Location).Path
$guardApk = Join-Path $bundleRoot '03_项目源码\app\build\outputs\apk\debug\app-debug.apk'
$helperApk = Join-Path $bundleRoot '03_项目源码\adb-auto-enable\app\build\outputs\apk\debug\app-debug.apk'
$adbTools = Join-Path $bundleRoot '02_电脑EXE\tools'
$output = Join-Path $bundleRoot '重新编译输出\电脑客户端'

dotnet publish '.\03_项目源码\pc\SonyVolumeGuiKillerPcManager.csproj' `
  -c Release -o $output `
  "-p:AdbToolsDir=$adbTools" `
  "-p:GuardApk=$guardApk" `
  "-p:AutoEnableApk=$helperApk"
```

这三个输入路径必须显式指定：源码中的默认路径适配原开发目录，并不一定适配这个汇总目录。输出应包含 EXE 和 `apk` 子目录；请一起分发。命令输出另含调试符号时，不影响运行。

辅助 APK 是 EXE 内嵌资源，修改它之后，必须重新编译 PC 才能更新内嵌版本。仅替换 `01_电视APK` 中的文件，不会自动改变 EXE 内部的 APK。

### 9.5 更换电脑重新编译时注意签名

本项目采用 debug 构建以支持现有授权流程。另一台电脑生成的 debug 签名可能不同，即使包名和版本号相同，也可能无法覆盖原应用。安装前先比较签名与版本，保留备份，不要通过盲目卸载来处理。

## 10. 重新编译后的验收与分发

1. 确认两个 Android 工程与 PC 发布均成功，查看测试和 lint 结果。
2. 打开新 EXE，确认默认 IP 是 `192.168.1.111`，手动修改仍可用于连接。
3. 在已备份的测试电视上安装，检查授权、无障碍和真实音量键效果。
4. 检查 ADB 中断、应用进程回收、待机唤醒后的恢复，并记录耗时。故障注入应只在可恢复连接的测试条件下操作。
5. 分别记录三个程序版本。更新辅助 APK 时，也记录客户端内嵌的是哪个版本。
6. 发布时带上 EXE 旁的 `apk` 目录、使用说明和校验清单，不包含授权密钥、个人设备备份与日志。

本目录的 `SHA256SUMS.txt` 用于核对文件。单个文件可这样查看：

```powershell
Get-FileHash -Algorithm SHA256 '.\01_电视APK\SonyVolumeGuiKiller-1.0.4-debug.apk'
```

将输出与清单中对应路径的哈希值比较；修改或重新编译后，需要重新生成对应校验值。
